## 1. 定位与运行方式

Local Pi 是基于 Pi SDK 的本地多会话终端编程助手。Node.js 要求见 [package.json](../package.json)（当前声明为 22.19+）；使用 TypeScript、Pi Coding Agent SDK 与 Pi TUI 1.3.0。长期记忆使用 Mem0 OSS SDK 3.3.1、SQLite 和 Markdown；Mem0 的原生 SQLite 依赖 `better-sqlite3` 需与本机 Node ABI 匹配，安装细节见[记忆说明](memory.md)。操作日志则使用 Node 内置 `node:sqlite`。

| 入口 | 当前行为 |
| --- | --- |
| `local-pi` / `npm start` | 默认多会话全屏 TUI；从当前目录启动，可用 `--cwd` 指定项目 |
| `--continue` / `--session <JSONL>` | 恢复最近会话或指定会话；两者互斥，指定文件须匹配工作目录 |
| `--agent-dir` / `--model` | 指定 Pi 配置目录或启动模型 |
| `--classic` | 进入原生 Pi 界面，不使用自定义多会话管理 |
| `--print` / `--doctor` | 分别执行单次任务、检查配置；诊断不发送模型请求 |

## 2. 会话、历史与上下文

- 每个打开的会话有独立 SDK 运行实例、草稿、滚动位置、工具状态、消息队列和运行状态。切换视图不停止旧任务；可用 `/stop [编号]` 单独停止。退出程序会停止后台任务。
- `/new` 可指定工作目录；优先复用无草稿的临时空白页。首次提交才进入正式历史，未发送草稿留在内存。SDK JSONL 保存对话，辅助索引用于列表、标题和恢复；默认存放于 `.local-pi/sessions/` 并按工作目录分组。
- `/sessions` 与 `/resume` 共用列表，合并当前项目历史和已打开会话，按 fork 关系分组；有滚轮、鼠标、当前标记、未读及所选会话详情。
- `/fork` 从完整、已保存的消息复制截至该点的对话到独立会话。原实例和任务继续；新会话默认讨论模式，继承历史模型与等级，不自动重发选中消息，也不复制源队列或运行状态。
- `/tree` 在同一会话文件内浏览、搜索、标记并切换历史分支；仅空闲时切换，可选摘要（需要模型调用）。`/tree` 和 `/fork` 都不复制或恢复代码文件。
- 运行中 Enter 追加指令，后续消息进入独立队列；可取回未发送队列。`/compact` 在空闲时手动压缩；压缩期间输入暂存，成功后继续交给 SDK。

## 4. 文件快照、任务差异与恢复

**从记录实际修改，到审阅、恢复，已经接通。** 默认多会话入口在执行任务或运行手动终端命令时记录文件变化；目前未在 `--classic`、`--print` 接入同样的文件恢复流程。

1. **记录实际操作。** 原生 `edit`／`write` 保存文件的前后版本并做版本核验。PowerShell／Bash、手动命令和其他可能写文件的工具，在调用前后记录有范围和上限的文件状态。任务起止扫描也记录未能归属到工具操作的变化，单独显示。
2. **展示差异。** 任务下方“查看变更”或 `/changes` 打开本轮面板；支持文件列表、彩色 diff、切换轮次、快照问题和记录范围。面板展示历史快照，不跟随工作区后续修改改变。
3. **预览后撤销／重做。** `/undo`、`/redo` 或面板可选择单文件、整轮操作；先预检和预览，确认时复检版本。整轮有冲突会整体拒绝，可单独处理无冲突的文件。基线是本会话首次修改目标文件前的版本，会保留此前已有的本地修改。
4. **处理失败或中断。** 确认后先写日志和备份，再逐文件操作；多文件操作不是文件系统事务。`/recovery` 可恢复未完成的撤销／重做至操作前备份；对结果不确定的普通工具操作，则由用户检查后确认保留现状并解除阻塞。

恢复会核对哈希、文件身份、时间戳、模式及后续写入记录。缺少备份、脚本范围不完整、归属不明或文件已变化的项目，不会被当作可自动覆盖的目标。恢复不会回退聊天、提交、暂存区、远程状态或进程；也不依赖 Git，所以 SVN 项目和普通文件夹可使用。

普通扫描最多 10,000 项、64 MiB，单文件快照上限 2 MiB；版本核验的上限与可自动恢复的上限不同。默认排除版本库元数据、依赖、构建输出和 Pi 存储目录，不跟随符号链接或目录联接。二进制及超出 diff 上限的文本可有字节快照，但不展示文本差异。扫描不到工作目录外的脚本变化，也不备份数据库事务或远程操作。

| 会话根目录下的数据 | 用途 |
| --- | --- |
| `file-snapshots/<任务 ID>/` | 每轮文件清单与历史差异 |
| `file-snapshots/restore-operations/` | 恢复预检、日志与操作前备份 |
| `workspace-operations/operations.sqlite`、`blobs/` | 按顺序保存操作元数据及按哈希存放的原始字节 |
| `workspace-coordination/` | 跨进程租约与版本事件 |

## 5. 同目录并发与写入保护

多个会话可在同一真实目录工作；保护粒度从**整轮任务**改成了**实际文件／目录操作**：

- 同一文件的读写通过租约排序，不同文件可并行。脚本等难以提前确定写入范围的工具，执行期间独占相关目录的写入。
- 文件排队期间若版本改变，写入会拒绝并要求先重新读取。脚本结束会使执行期间的部分读取凭据失效；codemode 的嵌套工具沿用父调用范围，并分别记录。
- 同一会话根目录的多个 Local Pi 实例参与跨进程协调。恢复操作会避开正在运行的相关操作，并阻止覆盖后来产生的改动。
- 外部编辑器、使用不同会话根目录的实例，以及绕过工具直接操作的扩展不受租约约束。恢复前的版本复检能降低覆盖风险，但不能提供操作系统级隔离。

## 6. 全局／项目长期记忆

全局记忆跨项目共享，项目记忆在项目内跨会话共享。项目身份按最近的 Git／SVN 根目录确定，没有仓库标记时按工作目录；会话用于记录来源，不单独建记忆库。

- **正文与索引分离：** 每个范围各有一份可直接编辑的 `MEMORY.md`，正文以 Markdown 为准。Mem0 与 SQLite 用于检索索引、队列、回执和删除记录；旧数据库可迁移成 Markdown，索引可重建。
- **自动提取：** 配置后按会话采集新内容。默认达到约 20 个用户轮次、8,000 估算 Token，或有待处理内容且空闲约 10 分钟时安排后台提取。可封存、重试和在后续启动时恢复；不常驻进程，也不批量回填启用前的旧聊天。
- **提取与召回：** 自动条目要求用户原话或验证记录作为证据。短记忆直接读取 Markdown；超预算时通过 Embedding 检索相关项目和全局条目。支持 OpenAI 兼容 Embedding 或本地 Ollama；本地 Embedding 不等于自动提取模型也在本地运行。
- **用户管理：** `/memory status`、`used` 查看状态和召回；`add`、`list`、`search`、`edit`、`delete` 管理；`auto on|off`、`extract`、`retry`、`reindex` 控制后台整理和索引。手动管理不改变模型的项目写入权限。
- **存储范围：** 正文、索引和队列位于 `<agent-dir>/local-pi-memory/`，不写入业务项目的规则文件。删除阻止将来从该库召回，不追溯修改已有聊天或摘要。

## 7. 当前边界与核查范围

- **系统沙箱、自动创建独立工作副本、审阅后回写原目录仍未实现。** `--cwd` 只是工作目录；命令、已加载扩展和 MCP 仍各自使用实际执行环境。文件撤销能处理已核验的文件修改，不能阻止命令越界或撤回远程副作用。
- **尚无面向 SVN／Git 危险命令的专用审批。** 文件变更恢复是事后保护，不代表已阻止执行危险操作，也不代表可以恢复任意改动。
- **后台运行依赖 Local Pi 进程。** 持久化历史、快照和记忆队列，不等同于关掉程序后模型任务仍在运行。
