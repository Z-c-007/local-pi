# Local Pi

基于 Pi SDK 的个人终端编程助手。当前固定使用 `@earendil-works/pi-coding-agent@1.3.0` 和官方 `@earendil-works/pi-tui@1.3.0`。默认提供多会话终端界面，每个会话保留独立 SDK 运行实例；原有完整 Pi TUI 可通过 `--classic` 使用。

## 启动

需要 Node.js 22.19+、npm。Git 用于查看代码变更。

```powershell
cd D:\learn\Pi
npm ci --ignore-scripts
npm start
```

在交互式 PowerShell 或 Windows Terminal 中运行。支持中文输入、流式回复、工具执行展示、后台会话与独立中断。

## 在任意项目目录启动

在本项目目录构建并注册本机命令（无需发布到 npm）：

```powershell
cd D:\learn\Pi
npm run build
npm link --ignore-scripts
```

之后在要操作的项目目录运行：

```powershell
cd D:\你的项目
local-pi
# 恢复当前项目最近的会话
local-pi --continue
```

`local-pi` 与原有 `pi` 命令分别使用各自的入口。命令默认以启动时所在目录工作。本机链接指向 `D:\learn\Pi`，请保留该目录；修改源码后执行 `npm run build`，并重新启动命令即可加载更新。切换 Node 版本或 npm 全局目录后可能需要重新注册。

如需移除本机命令，在终端执行 `npm uninstall -g local-pi`；项目源文件会保留。

## 多会话与后台任务

默认执行 `local-pi` 即进入多会话界面。切换会话只改变显示和输入目标，不调用旧会话的 `abort()` 或 `dispose()`。A 正在执行时可以新建或切到 B，A 会继续处理模型请求和工具执行。

| 操作 | 命令或快捷键 |
|---|---|
| 新建同项目会话 | `/new` 或 Ctrl+N |
| 新建另一项目会话 | `/new "D:\其他项目"` |
| 统一会话列表 | `/sessions`、`/resume` 或 Ctrl+P；方向键选择、Enter 确认、Esc 取消 |
| 按编号切换 | `/switch 1` |
| 为当前会话命名 | `/name 修复登录问题` |
| 分叉会话 | `/fork` 选择历史消息，Enter 创建独立会话，Esc 取消；保留到所选消息（含） |
| 会话树 | `/tree` 使用官方选择器浏览、搜索、标记和切换当前会话分支；空闲时可切换，不回滚文件 |
| 导出 | `/export` 默认在当前项目导出 HTML；`/export "路径.html"` 或 `/export "路径.jsonl"`；已有目标不覆盖 |
| 重载 | `/reload` 重载当前空闲会话的扩展、技能、提示模板、主题、项目说明和快捷键 |
| MCP 管理 | `/mcp` 使用官方管理页；支持 `/mcp login 名称`、`/mcp logout 名称`、`/mcp reconnect 名称` |
| 直接执行命令 | `!命令` 手动运行终端命令；`!!命令` 的输出不进入模型上下文；Windows 使用 PowerShell |
| 推理等级 | `/thinking` 打开官方选择器，方向键选择、Enter 确认；Shift+Tab 循环切换；也可 `/thinking high` 直接设置 |
| 主题 | `/theme` 打开官方主题选择器，方向键预览、Enter 保存、Esc 恢复；也可 `/theme dark`、`/theme light`、`/theme system`、`/theme light/dark` 或资源主题名称 |
| 设置菜单 | `/settings` 使用官方完整菜单，输入文字搜索、Enter/Space 更改、Esc 返回或关闭；修改即时保存 |
| 模型选择 | `/model` 或 Ctrl+L 打开官方搜索选择器；Enter 只切换当前会话，Ctrl+S 同时保存默认模型；`/model provider/id` 直接切换 |
| 会话统计 | `/session` 打开只读详情、SDK 累计用量、上下文及最近任务信息；不写入模型历史 |
| 快捷键帮助 | `/hotkeys` 显示实际绑定和冲突；统计与帮助页用方向键/PageUp/PageDown 滚动、Esc 关闭 |
| 追加指令 | 运行中 Enter：SDK steering 队列，当前工具轮次完成后处理 |
| 排队后续消息 | Windows / WSL：Ctrl+Q；其他系统：Alt+Enter；当前工作结束后由 SDK 继续 |
| 取回队列 | `/dequeue`；Windows / WSL：Alt+Q；其他系统：Alt+Up；将未发送消息恢复到当前会话草稿 |
| 手动压缩 | `/compact [摘要要求]`，当前会话需空闲，不会自动中断任务 |
| 复制回答 | `/copy` 或 Ctrl+X；快捷键优先复制手动选中的内容（关闭自动选中复制时） |
| 外部编辑器 | `/editor` 或 Ctrl+G；使用 Pi 的 `externalEditor` 配置或 `VISUAL` / `EDITOR` 环境变量，退出编辑器后回填草稿 |
| 剪贴板粘贴 | Windows / WSL：Alt+V；其他系统：Ctrl+V。读取文件、截图或普通文字，支持 `app.clipboard.pasteImage` 自定义快捷键 |
| 思考显示 | Ctrl+T 折叠／展开；`/thinking-display` 循环折叠、展开、隐藏，也可附 `collapse`、`expand`、`hide` |
| 工具结果 | 点击工具标题单独展开／收起；Ctrl+O 或 `/tools` 批量切换，也支持 `/tools expand`、`/tools collapse` |
| 停止当前任务 | `/stop` 或 Esc |
| 停止指定会话 | `/stop 2` |
| 关闭空闲会话 | `/close` 或 `/close 2`；运行中会话先停止，或保留在后台 |
| 退出整个程序 | `/quit`；有后台任务时选择是否停止全部并退出 |

会话各自保留输入草稿、滚动位置、讨论／执行模式和工具状态。底部显示会话编号、运行状态及未读标记；后台任务完成后给出通知。扩展需要确认或输入时，该会话标记为“等待处理”，切回后回答，不占用其他会话的输入。运行中的普通输入进入 SDK 追加队列，不中断正在执行的模型请求或工具；后续消息快捷键进入独立 follow-up 队列。待发送消息显示在输入框上方，队列始终属于原会话。

steering 在当前助手工具轮次结束后处理，follow-up 在工具与追加指令处理完后继续；具体一次取一条或全部取出由 `/settings` 的原生 Steering / Follow-up mode 控制。取消任务前，当前界面会将尚未发送的队列取回草稿；已被 SDK 消费的消息无法撤回。空闲时后续消息快捷键和 Enter 一样开始任务。追加和后续消息共用当前 SDK 运行周期的计时与用量汇总。

压缩复用 `session.compact()`。由于官方手动压缩会先中断当前操作，Local Pi 在入口检查空闲状态；压缩期间仍可切换会话，输入会暂存于该会话的压缩后队列，成功后再交回 SDK 执行。失败时保留未发送队列供取回，停止压缩会恢复到草稿。外部编辑器复用官方临时文件和进程流程，只暂停终端显示与输入，不停止后台 SDK 任务；编辑结果回到原会话，不自动发送。编辑器失败保留原草稿。

推理等级复用官方 `ThinkingSelectorComponent` 和 SDK 的 `getAvailableThinkingLevels()`、`setThinkingLevel()`、`cycleThinkingLevel()`，只展示当前模型支持的等级。普通选择只调整当前会话；选择器内按 Ctrl+S 可同时保存为默认等级，后续新会话沿用。正式会话恢复自己的等级；未提问的临时页关闭后不保存。修改等级不会中断或重新发送正在执行的请求，后续模型请求使用新等级。状态栏分别显示推理等级和思考内容的显示状态。

快捷键读取 Pi 配置目录的 `keybindings.json`，支持官方的 `app.thinking.cycle`、`app.thinking.save` 配置；默认分别是 Shift+Tab、Ctrl+S。原有配置文件不会被改写。

本界面使用 `app.model.select`（默认 Ctrl+L）选择模型，`app.models.save`（默认 Ctrl+S）在选择器内保存默认模型。会话切换和新建分别为 `local.session.select`（Ctrl+P）、`local.session.new`（Ctrl+N）；`app.interrupt`、`app.clear`、`app.exit`、`app.tools.expand`、`app.thinking.toggle` 也读取已有配置。编辑器、模型和等级选择器各自的相同按键属于不同上下文，`/hotkeys` 会列出注册表报告的重叠。配置变动重启后生效。

设置菜单沿用官方 `SettingsSelectorComponent` 和 `SettingsManager`，主题、思考显示、自动压缩、模型专属推理等级、图片显示、输出留白、输入框、硬件光标、滚动条、选中复制、滚轮、队列模式、会话树过滤和 HTTP 超时等在本界面即时应用。双击 Esc 的原版动作、Mermaid、分享、缓存未命中通知、原版启动显示及退出输出等功能仍未完整接入；相关设置保存后会明确提示在 `--classic` 中使用。多会话固定全屏，菜单中的 TUI 模式选项会提示并恢复为 fullscreen，不会中断后台任务切换布局。设置菜单的 Esc 只关闭菜单，不撤销已保存的修改。

图片粘贴复用官方剪贴板读取与格式处理：先读取复制的文件路径，再读取截图并保存为临时图片、在输入框插入路径，最后回退到普通文字。粘贴本身不发送模型请求；提交后沿用 Pi 的路径流程，模型可用原生 `read` 工具读取图片。模型需要支持图片输入。异步读取始终回到发起操作的会话草稿，切换不会串图；发送、清空、替换草稿或关闭会话会丢弃尚未完成的粘贴。没有可粘贴内容或读取失败时显示提示。

推理等级的输入框边框和 Working 提示沿用官方主题颜色。主题读取 SDK 已保存的配置，使用官方主题控制器处理终端颜色查询、明暗切换和 `light/dark` 配置，并注册 SDK 发现的主题资源。`/theme` 保存到 Pi 设置；同一配置目录下已打开的会话同步新选择。主题预览取消不保存，切换主题保留单条思考块和工具的展开状态。主题热更新范围沿用官方控制器；项目和包资源变动后可对空闲会话执行 `/reload`。

输入框下方复用原生 `FooterComponent`，显示会话累计输入、输出、缓存、上下文占用、模型和扩展状态。上下文占用沿用 SDK 的统计或估算，不等同于累计消耗。原生底栏如显示费用，它来自 SDK 的模型价格计算，不代表套餐扣额；套餐剩余额度未接入。

Working 显示当前任务总耗时，每次提交任务独立计时，包含等待确认、模型响应、工具执行、自动重试及自动压缩。后台继续计时，切换视图和工具轮次不重置；完成、失败、停止后在聊天区保留“本次耗时”和该轮 Token 汇总。汇总使用 SDK 累计统计差值，思考 Token 不重复加到输出里。用量全无时显示“未知”，部分成功响应缺失用量时注明“不完整”；取消或失败时只能汇总已经收到的用量。

任务统计以 SDK 自定义条目保存在会话分支中，不作为消息发送给模型，恢复对话可继续查看。旧历史没有计时记录，不补造耗时；意外退出留下的未结束记录显示统计未知。`/theme` 等本地操作不触发模型，也不生成任务统计。尚未接入的原生命令（例如 `/import`、`/share`）和未知命令会明确提示，不作为普通指令发送给模型；已注册的扩展、提示模板和已启用的 `/skill:名称` 仍交给 SDK 处理。

`/fork` 复用 SDK 的 `SessionManager.createBranchedSession()`，在独立 manager 上复制当前分支到所选消息，再创建独立运行实例；不调用原 runtime 的替换式 fork，不中断原任务。选择器仅列出完整、已保存的用户消息与正常结束的助手消息，不允许分叉到缺少工具结果的边界。运行中可从已完成部分分叉；取消选择不改变当前会话。新会话默认只读讨论，继承分叉位置的上下文、模型和推理等级，不自动发送请求，也不复制源会话的草稿、待发送队列和运行任务。历史任务报告不作为子会话的最近任务展示，SDK 累计统计仍包含继承历史的用量。列表和 `/session` 可查看来源，关闭后仍可恢复。扩展的 `session_before_fork` 可取消操作，新实例收到 reason 为 fork 的 `session_start`。该命令只分叉对话，不复制工作目录、不回滚文件；两个会话仍共用当前代码，同目录执行限制继续生效。

`/tree` 复用官方 `TreeSelectorComponent` 与 `session.navigateTree()`，浏览当前会话文件内的分支。可以搜索消息、编辑节点标签和复制文本，过滤方式沿用 `/settings`。选中用户消息时，SDK 回到它之前的位置，并把该消息放回此会话草稿；已有草稿会保留在后面。旧分支仍留在原会话文件中。可以选择不摘要、摘要或输入自定义摘要要求，摘要会调用模型，Esc 取消摘要或选择器。当前会话正在运行时拒绝切换分支，其他会话的后台任务继续。会话树不恢复代码文件；`app.session.tree` 可在 `keybindings.json` 中绑定，双击 Esc 动作尚未适配。

`/export` 复用 SDK 的 HTML 与 JSONL 导出，不发起模型请求。默认导出到当前项目，文件名包含会话 ID 与时间；可指定带引号的完整或相对路径。HTML 带官方查看界面及全部分支，JSONL 导出当前分支，可用 `--session` 恢复。目标父目录需存在，已有文件不会覆盖；只有已提交过提问的会话可导出。导出内容按 SDK 原样保留，`!!` 记录也在其中。

`!命令` 直接调用 SDK 的 `executeBash()`，Windows 复用官方 PowerShell operations，其他系统使用 SDK 的 Bash 配置；扩展的 `user_bash` 拦截和自定义 operations 也保留。命令在此会话目录执行，不自动请求模型，输出使用官方命令卡片展示并加入后续模型上下文；`!!命令` 仍保存在会话记录，但模型转换时排除。Esc 或 `/stop` 只停止该会话的命令。直接命令需当前会话空闲，并遵守同目录执行互斥；运行期间仍可切换会话，普通新消息保留为草稿，等待命令结束后再发送。讨论模式限制模型的工具，用户自己输入的 `!` 命令仍会执行。

`/reload` 复用 SDK 的 `session.reload()`，只重载当前空闲会话，不替换 Agent 或聊天文件，保留草稿及历史；其他会话不重载、任务继续。快捷键注册表原地更新，现有输入框也能使用新绑定。资源加载错误会显示通知。仅切换主题保留折叠状态；完整资源重载会重新构建消息组件。

MCP 沿用 Pi 自带的 MCP、codemode 和 tool-search 扩展，遵守原生内置扩展启停配置。全局服务写在当前配置目录的 `mcp.json`，格式为 `{"mcpServers":{"名称":{"command":"程序","args":[]}}}` 或 `{"mcpServers":{"名称":{"url":"https://服务地址/mcp"}}}`。项目 `.pi/mcp.json` 的加载遵守 SDK 的项目信任设置。认证写入该配置目录的 `mcp-auth.json`，日志为 `mcp.log`；新增配置后执行 `/reload`。官方管理页支持认证、重连、启停、暴露方式和工具查看；Ctrl+P、Ctrl+N 仍可切换或新建会话，切回保留菜单位置。讨论模式只向模型开放本地读取搜索工具，并在调用事件中阻止其他工具；执行模式开放已配置的 MCP 工具及 SDK 选择的发现工具。已配置且启用的服务在会话启动时自动连接，OAuth 登录由用户明确发起。

输入框使用官方 `CustomEditor`，任务提交后会在顶部边框显示 `⠋ Working (Esc to interrupt)` 动画，等待首个响应、流式回复和执行工具时持续显示。自动重试和上下文压缩分别显示 `Retrying`、`Compacting context`；等待确认时显示静态 `Waiting for input`。任务结束、失败或取消后移除提示。讨论和执行模式都会显示 Working。

切换会话只暂停原视图的动画，不影响其 SDK 任务；切回后根据该会话的实际状态恢复提示。扩展的 `setWorkingMessage()`、`setWorkingVisible()`、`setWorkingIndicator()` 均接到当前会话；消息和动画配置支持无参恢复默认，显示开关使用布尔值。动画基于公开的 Pi TUI `Loader`，没有导入 SDK 内部的状态组件或修改依赖源码。

聊天区的用户消息为靠右的背景气泡，气泡内文字保持左对齐；助手回答靠左，代码块保留较宽的空间。窄窗口会自动缩小两侧留白。消息使用官方 `UserMessageComponent`、`AssistantMessageComponent` 和主题渲染，保留 Markdown、代码高亮及中文换行能力。

思考过程默认折叠；点击“思考过程”展开，点击思考正文收起，也可以通过上述命令或快捷键控制当前会话的全部思考块。隐藏仅影响显示，不修改模型的推理等级，也不删除对话记录。只有模型接口实际返回思考内容时才会出现思考块。每个会话独立保留本次打开期间的显示偏好和展开状态，流式更新不会重置单条消息的展开状态。

工具默认只显示名称、状态和路径／命令，展开后使用官方 `ToolExecutionComponent` 展示当前已收到的完整记录，不再按 1800 字符截断。执行中可查看已收到的工具输出；失败会在标题标明。查看展开内容时暂停自动跟随，避免突然跳到输出末尾；滚动到底部或点击“回到最新输出”可以继续跟随。工具自身在读取或执行时产生的输出限制仍然有效。

`/sessions` 和 `/resume` 使用同一个列表：每个会话 ID 只占一行，按最近活动排序，合并当前项目的历史会话和本进程已打开的会话。列表显示名称、运行／等待／空闲／历史状态、当前会话、未读标记、活动时间及短 ID；其他项目的已打开会话会额外显示工作目录，方便切回。未命名会话使用第一次任务的简短文本作为标题，也可以 `/name 名称` 手动命名。

选择运行中的会话会直接切回原来的 SDK Agent 实例；选择已关闭的正式历史会话才会从 SDK 记录恢复。启动时先显示“新对话（临时）”，没有提问就不写入索引、不计入历史；模型、等级、模式、名称和设置操作也不使它成为正式会话。首次提交提问后立即进入历史，即使随后失败或取消也保留。

`/new` 或 Ctrl+N 优先复用当前项目中没有草稿、没有任务的临时空白页，避免连续创建空页；确实需要新 Agent 时才创建，不复制旧会话上下文，初始为只读讨论。有未发送文字或粘贴图片路径的页面保留为当前程序内的临时草稿，可通过会话列表切回，但不算历史记录；退出程序不保存未发送草稿。`/close` 关闭临时页会丢弃它，关闭正式会话只关闭运行实例，历史仍可重新打开。旧版本产生的空白索引会隐藏，原文件不自动删除。

第一版限定在同一个 `local-pi` 进程仍然打开期间后台执行；退出程序会停止所有任务。当前进程内，同一真实工作目录只允许一个执行模式任务运行，其他会话仍可只读讨论；需要同时修改同一仓库时请使用不同的 Git worktree。这个限制不协调其他独立启动的 `local-pi` 进程。

多会话界面使用官方 Editor、消息组件、SelectList、ScrollView、模型及设置选择器等组件，但不是完整的 `InteractiveMode`。`/model`、`/login`、`/settings` 和项目扩展命令可用；依赖完整 TUI 私有布局、特殊渲染或自定义终端面板的扩展，请使用原入口：

```powershell
local-pi --classic
```

`--classic` 保留上游完整界面和设置菜单，其原生会话切换仍会停止当前任务。默认多会话实现没有修改 `node_modules` 或调用 TUI 私有绑定方法。

主题控制器、主题资源注册、Git 底栏数据提供器、原生命令清单、完整内置扩展清单、MCP 配置／认证存储和 PowerShell operations 没有全部从 1.3.0 的公开 SDK 导出。`src/tui/pi-ui.ts` 集中读取这些官方模块，并在加载前严格检查依赖版本；升级 Pi 时需要先复核此兼容层。消息、选择器、会话树和终端命令组件本身使用公开组件，没有修改依赖源码。

默认使用你现有的 Pi 配置目录 `~/.pi/agent`，可复用已有的认证、模型及设置。需要配置时，在 TUI 中执行 `/login`、`/model`；自定义 API 接口在该目录的 `models.json` 中配置。不要把凭证写入项目源码或提交到 Git。

```powershell
# 检查配置和可用模型，不发送模型请求
npm start -- --doctor

# 让助手操作另一个代码项目；带空格的路径需要引号
npm start -- --cwd "D:\learn\your-project"

# 恢复这个项目的最近会话
npm start -- --cwd "D:\learn\your-project" --continue

# 为本次运行指定模型（替换为 doctor 输出中的实际标识）
npm start -- --model "provider/model-id"

# 单次任务；也适合非交互式终端
npm start -- --cwd "D:\learn\your-project" --print "解释项目结构"

# 使用独立配置目录，不复用全局 Pi 配置
npm start -- --agent-dir ".local-pi\agent"
```

`--cwd` 是工作目录，不是沙箱。内置工具以当前用户权限读写文件、执行命令。应用沿用 SDK 的资源发现机制，会加载配置中的扩展和项目资源；只在你信任的项目和扩展上运行。

## 已有能力

- 默认多会话 TUI；`/login`、`/model`、`/settings`、`/new`、`/resume`、`/sessions`、`/quit`；`--classic` 使用完整 Pi TUI。
- 新会话默认讨论模式：仅向模型开放 `read`、`grep`、`find`、`ls`。
- `/execute`：进入执行模式，增加 `edit`、`write`，以及 Windows 的 `powershell` 或其他系统的 `bash`。
- `/discuss`：返回只读讨论模式。切换保留对话，不自动开始任务；任务执行中需先停止再切换。
- 状态栏持续显示模式；`/project` 显示当前目录、模式、模型和工具。
- `/changes`：展示 Git 状态、未暂存和已暂存 diff；未跟踪文件仅列出名称。
- `/code-review [关注点]`：加载代码审查提示模板。
- 会话保存在本项目 `.local-pi/sessions/`，按目标目录分组；与原 Pi 的默认会话目录分开。
- 项目中的 `.pi/` 资源和 `AGENTS.md` 通过 Pi 默认加载器发现。

默认 `/resume` 与 `/sessions` 完全同义，不再扫描所有项目的历史。历史文件保留在原处，无需迁移；以前其他项目及测试目录的记录不会混进当前项目列表。`--classic` 中 `/resume` 仍是上游 TUI 的选择器。如需恢复某一目标项目最近的正式 Local Pi 会话，使用 `--cwd ... --continue`，旧空白记录会被跳过；没有正式历史时打开临时新对话。可以通过 `--session <完整 JSONL 路径>` 恢复已有对话的指定会话，并用 `--cwd` 指定其原工作目录。

模式变化记在会话的当前分支中。恢复正式会话时沿用其模式；旧会话没有模式记录时默认讨论，新建会话也默认讨论。SDK 继续负责 JSONL 对话记录；每个项目的 `metadata/` 目录只索引正式会话，临时页的快照仅放在内存中。如果首次提交在 SDK 写入用户消息前就失败，索引暂存这条已提交的问题，恢复时可查看而不会自动重发；SDK 已保存真实用户消息后便移除这份暂存。不把未发送的草稿或模式设置伪装成用户消息。`--classic` 和 `--print` 仍沿用 SDK 的空白会话行为。

直接发送 `/execute` 即由程序切换，无需模型判断；不需要代码块。切换会同步一条模型可见的状态通知，每轮任务还会更新当前模式说明，避免历史对话中的“仍在讨论模式”造成误判。切换后直接发送“开始改”即可延续已有方案。

讨论模式会收紧模型工具列表，并在工具调用事件中拦截其他工具。这是应用层限制，不是系统沙箱；不阻止用户手动使用 TUI 的 `!` 命令，也不隔离已加载扩展自身的行为。`/changes` 仍可由用户直接调用来查看 Git 变更。

`--print` 同样遵守当前会话模式：新会话为只读，恢复会话则沿用保存的模式。

## 第一次写代码

项目包含一个正常通过测试的小示例：

```powershell
npm --prefix examples/workspace test
npm start -- --cwd examples/workspace
```

先在 TUI 中讨论方案：

> 请阅读 sum 和测试，讨论如何增加数字类型校验，先不要修改。

确定方案后，单独输入 `/execute` 切换模式，再输入任务：

> 请给 sum 增加数字类型校验：参数不是 number 时抛出 TypeError。先读代码和测试，再修改实现、补充测试并运行 npm test，最后说明变更。

自动测试使用本地模拟模型驱动真实 Pi SDK，覆盖代码修复、模式同步、写入限制和会话恢复；另有多会话测试验证后台 PowerShell 任务、独立中断、输出隔离和同目录执行冲突限制。内存终端测试覆盖官方组件的会话选择、草稿恢复和后台交互路由。测试不调用付费模型，也不会修改示例项目。通过模拟测试并不代表你的真实模型认证已验证。

所有测试的会话、索引和认证缓存均写入各自的临时目录，与正式 `.local-pi/sessions/` 分离。会话测试也覆盖空白页不持久化、临时草稿切回、旧空索引隐藏且不删除、首次提交失败/取消后保留、正式历史恢复、按 ID 去重和项目筛选。

原生入口回归还覆盖会话树导航和旧分支保留、HTML／JSONL 导出、重载时后台任务继续、手动终端命令的目录／取消／上下文排除，以及本地 MCP 子进程的 direct 与 codemode 调用、菜单切换恢复。`npm test` 将文件并发限制为 4，避免原生子进程和图片处理同时启动造成短等待用例超时。

## 开发

```powershell
npm run check
npm test
npm run build
node dist/main.js --help
```

- `src/main.ts`：TUI 和单次任务入口。
- `src/agent/runtime.ts`：SDK 会话、工作目录、工具和资源配置。
- `src/agent/mode.ts`：讨论／执行模式、工具列表和模式记录恢复。
- `src/agent/session-pool.ts`：独立运行实例、任务生命周期、事件和输出隔离。
- `src/agent/session-catalog.ts`：正式会话索引、SDK 历史合并和按项目恢复，空白页只生成内存快照。
- `src/tui/multi-session.ts`：官方终端组件组成的会话列表、聊天、输入与确认界面。
- `src/tui/transcript.ts`：左右消息布局、官方消息组件、思考显示及工具结果展开。
- `src/tui/working.ts`：官方编辑器、Working 动画适配和每个会话的显示设置。
- `src/tui/keybindings.ts`：注册原生推理等级动作，读取已有快捷键配置。
- `src/tui/pi-ui.ts`：固定版本的官方 UI 服务兼容层。
- `src/tui/clipboard.ts`：原生剪贴板读取流程与各会话草稿的异步粘贴隔离。
- `src/tui/settings.ts`：官方设置菜单配置、SDK 保存回调和当前界面适用范围。
- `src/tui/info-panel.ts`：不进入模型上下文的只读滚动页面。
- `src/tui/extension-panels.ts`：官方扩展自定义面板的会话归属、切换时隐藏／恢复和关闭清理；用于 MCP 管理页。
- `src/agent/task-metrics.ts`：每轮任务计时、SDK 用量差值与模型不可见的统计条目。
- `src/extensions/workspace.ts`：自己的命令和 TUI 状态扩展。
- `resources/coding.md`：附加的编程工作约定。
- `resources/prompts/`：提示模板。

后续先在这里增加你需要的命令、工具和工作流程；需要更复杂的终端面板时，再通过 Pi 的扩展 UI 接口定制。

官方参考：[SDK](https://pi.dev/docs/latest/sdk)、[TUI](https://pi.dev/docs/latest/tui)、[扩展](https://pi.dev/docs/latest/extensions)。实现以安装的 1.3.0 类型与示例为准。
